# 字趣

一个给孩子在本地使用的语文字词与古诗默写工具。孩子在屏幕上选择当前课次，听题后把答案写在自己的本子上，再根据完整答案自行批改。

## 现在的流程

1. 孩子在默写首页选择年级、册别和当前课次。
2. “当课复习”先按课本顺序默写本课词语表中的全部词语，再检查这些词语覆盖了哪些识字表、写字表的字，只为遗漏生字补充组词题；同词同拼音合并为一题。词语表整词都是目标字，补充组词以遗漏生字为目标。默认要求默写词语中的每个字及拼音，整次默写的题目都列在同一页，播放阶段不显示答案。每次播放会读两遍，第一遍结束 10 秒后读第二遍；空格播放或停止，左右键切换当前题目。播音直接使用浏览器自带的中文语音，不调用服务端语音接口。
3. 词库有教材语境时，默写、批改和订正都显示该题保存的同一句。红色（　）表示本题词语。点击“显示拼音”可查看整词拼音，所有汉字仍留空，批改时显示完整答案。
4. “历史复习”从本课之前的固定题目里最多选 20 题，每轮最多 5 道到期复练题，其余选还没完成整题的题。复练间隔为 5 天（120 小时）。写错过的题标「曾写错」，由历史错字承接到的固定题标「错字复练」。相同词语在不同课有各自的题目 ID 和学习状态。
5. 批改时，每题的所有字都参与计分，全部写对才算整题正确。任一字写错，本题记错一次，同时记录具体错字。是否显示拼音不影响计分。整题按“写对次数 − 写错次数”计算净正确次数，达到 1 即掌握。例如错 2 次，需要累计整题做对 3 次。
6. 古诗词只在当课做整篇默写，不作为历史复习题源。只显示题目拼音，题目、教材所列朝代与作者和全文都由孩子默写，不播放语音。
7. 同一次默写中，只要任意默写字出现在课文题目里，页面主标题和该课所有题卡都会持续把对应字替换为拼音，避免其他题泄露答案；批改时恢复中文题目。
8. 孩子写完后点击“结束默写”，点选答案中的错字并完成批改。一轮题目从展示到提交期间保持固定，家长补记影响后续轮次。继续练习时，系统先保存学习记录，再根据已保存成绩生成下一轮。订正页显示完整答案，实际错字标红。每道题第一次写错时整题订正 2 遍，此后本题每错一次增加 1 遍。
9. 家长看板首页显示默写打卡日历，可切换月份查看打卡天数和每天的默写题次。“学习进度”按题目展示已掌握、待巩固和未练的词语，同时汇总所选教材的考察字总数和已练题的去重字覆盖。在“错题本”中可切换待巩固和全部历史错题，并按当前范围打印。
10. 当课复习或历史复习完成后 3 天（72 小时）内，如果漏标了错字，可在“家长看板 → 默写记录”找到原场次并补记。系统按当场的计分范围更新原题及逐字统计，已经记错的题不会重复累计，保存确认后返回。超过期限的场次仍可查阅。
11. 当课复习和历史复习的批改题卡下方可标记“组词不合适”“读音不准”，两项可同时选择，再次点击可取消。标记会自动保存，不计为孩子的错字。家长可在“家长看板 → 词库问题”集中查看、导出当前列表的 JSON 清单，并在修改词库后标记已处理；也可重新打开。记录保留标记时的完整词语、拼音、目标字和课次，即使重建词库仍可定位原题。

## 词库

当前题库以本次提供的五·四学制教材为准，覆盖二年级上下册、三年级上下册、四年级上册，不用旧教材补齐未提供的册次。

```bash
npm run rebuild:catalog
```

重建脚本默认从仓库的 `textbook/` 读取材料，也可传入其他教材目录。脚本从 `小学语文教材结构化/` 读取课次、识字表、写字表和古诗，从 `默写词库-教材入库.md` 读取册末词语、拼音和语境，并按课次文件核对词语顺序。运行中的服务重启后加载新词库。

识字表、写字表中未被本课词语表覆盖的字，在重建时从课文、列词和选字练习补题，并应用 `scripts/textbook/reviewed-prompts.json` 中的人工审阅。词形不适合出题时可指定替换题，改了作答内容的题使用新 ID。

教材库包含 `catalog_meta`、`source_files`、`lessons`、`lesson_characters` 和 `questions` 五张表。每道册末词、生字补充题或整篇古诗在 `questions` 中占一行，保存题目 ID、题词、拼音、考察字和教材出处。字词题的挖空语境在重建时写入 `questions.hint_text`，当课、历史和订正都读取这份固定内容。

语境优先用本课原文。教材只给出篇名、列词或不同词形时，在 `scripts/textbook/reviewed-hints.json` 中按课次补一条短句，注明对应教材原文和行号。重建时核对出处并标记语境是教材原文还是据教材编写。重建后运行 `prompts:coverage` 检查语境是否齐全及其挖空格式。

- `data/ziqu-catalog.sqlite` 是从教材重建的只读词库，重建时先校验临时库再替换。
- `ZIQU_LEARNING_DB_PATH` 指向当前格式的学习库，默认文件为 `data/ziqu-learning-inherited-mastery.sqlite`，保存默写记录、题目成绩和具体错字。服务启动时会校验已有学习库的表结构。

## 学习记录

学习进度、成绩、默写记录和词库问题均写入服务端 SQLite。每次完成批改会新增一场记录，家长补记会更新原场次。学习库保留所有场次，打卡日历和默写记录可查看已保存的历史。

逐字成绩用于学习统计，日常掌握判定、订正和复练按固定题目计算。此前由历史错字承接到的固定题在家长页计为「已练待巩固」，整题作答次数仍由实际批改产生。这些题遵守原来的五天间隔，完成整题判定后按本题成绩继续安排。

可用以下命令查看学习库中按教材归类的逐字成绩。学习库和导出的报告含个人学习数据，请勿提交到仓库。

```bash
npm run --silent mastery:report -- data/ziqu-learning-inherited-mastery.sqlite
```

## 运行

运行环境使用 Node.js 24，前后端共用同一套出题规则。

```bash
npm install
npm run dev
```

然后打开终端中显示的本地地址。

启动页面只读取课次目录、当前课题目和必要的学习统计。切课和历史复习由后端按需返回题目，家长看板按需加载用于展示的题目和默写记录。词库查询结果在服务端缓存，接口支持 gzip 压缩。保存时增量写入新增或补记的默写场次。

生产运行：

```bash
npm run build
npm run start
```

## 代码结构与职责

```text
shared/
  types.ts                 词库、学习状态、默写记录的数据类型
  contracts.ts             HTTP 请求与响应的数据契约
  domain/
    characters.ts          目标字与整词字集、逐字批改键
    catalog.ts             课次范围、词语表与补充组词
    reviewPolicy.ts        掌握标准、历史错字复习间隔
    practice.ts            当课、历史与古诗题目生成
    reviews.ts             批改结果与原记录补记
    state.ts / wordIssues.ts  状态归一化、词库问题标记
src/
  App.tsx                  页面装配与加载状态
   styles.css               全局样式与共用布局
  app/
    useLearningData.ts     加载、请求取消、延迟保存、页面数据合并
    useAppController.ts    页面切换、练习阶段、批改草稿与操作衔接
  features/practice/       默写、古诗题卡、订正、标题遮罩、语音播放
  features/parent/         家长看板、最近记录、补记页面
  components/              跨页面共用的界面组件
  lib/                     浏览器 API 适配、日期与课次展示
server/
  index.mjs / app.mjs      进程启动、服务装配与依赖注入
  routes/                  URL、HTTP 方法与业务服务的对应关系
  http/                    JSON、压缩、静态资源传输
  services/                词库缓存、出题与学习记录的业务编排
  db/                      SQLite 表结构、连接与读写
  config.mjs               数据路径与运行配置
```

依赖方向：`src → shared`，`server → shared`；`shared` 不依赖 React、HTTP、SQLite 或前后端目录。后端路由调用服务，服务调用数据库模块；界面组件通过回调触发操作，不直接请求接口。`src/lib/api.ts` 按 `shared/contracts.ts` 构造请求、读取响应；这些类型描述现有协议，运行时校验规则沿用原实现。

当课复习、历史复习和古诗默写的题目由后端生成，完整词库也在后端缓存。语音播放、提示、逐字选择和练习阶段由浏览器负责。批改与补记在浏览器调用共享规则后保存状态。

`Lesson.unit` 对应 SQLite 的 `lessons.term`，其中 1 为上册，2 为下册。教材单元另存在 `lessons.unit_index` 和 `lessons.unit_name`。新增按单元复习时，按年级、册别和单元编号确定范围。

新增业务规则放到 `shared/domain` 的相应模块，新增页面放到对应 `features`，专用于某个功能的样式与组件放在一起。新增接口先更新 `shared/contracts.ts`。`src/lib/scheduler.ts`、`storage.ts`、`wordIssues.ts`、`src/types.ts` 和 `server/db.mjs`、`catalog.mjs` 保留为旧脚本的兼容导出入口，新代码优先引用具体模块。

验证命令：

```bash
npm test                 # 接口、数据库、业务规则与模块依赖边界
npm run prompts:audit    # 真实词库的题目与目标字检查
npm run --silent prompts:coverage  # 实际题库的语境覆盖、挖空格式及答案检查
npm run build           # 严格类型检查、未使用代码检查、生产构建
```

## 部署到服务器

可以直接使用 Docker 启动网站：

```bash
docker compose up -d --build
```

默认访问端口是 `5174`。Compose 将 `ziqu-data` 数据卷挂到 `/var/lib/ziqu`，服务使用其中的 `ziqu-learning-inherited-mastery.sqlite` 保存学习记录。更新容器时继续挂载同一个数据卷。全新安装会自动初始化学习库。课本词库随镜像更新，播音由浏览器提供。
