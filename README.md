# 字趣

一个给孩子在本地使用的语文字词与古诗默写工具。孩子在屏幕上选择当前课次，听题后把答案写在自己的本子上，再根据完整答案自行批改。

## 现在的流程

1. 孩子在默写首页选择年级、册别和当前课次。
2. “当课复习”先按课本顺序默写本课词语表中的全部词语，再检查这些词语覆盖了哪些识字表、写字表的字，只为遗漏生字补充组词题；同词同拼音合并为一题。词语表整词都是目标字，补充组词以遗漏生字为目标。默认要求默写词语中的每个字及拼音，整次默写的题目都列在同一页，播放阶段不显示答案。每次播放会读两遍，第一遍结束 10 秒后读第二遍；空格播放或停止，左右键切换当前题目。播音直接使用浏览器自带的中文语音，不调用服务端语音接口。
3. 词语有教材可挖空的句子时，默写一开始就显示。红色（　）表示本题词语，本轮其他答案用拼音代替。看句子不算查看拼音提示。“当课复习”点开拼音提示后，只统计仍需独立默写的目标字；提示字不记为本次写对，但批改时仍可主动标错。未查看拼音提示时，整词未标错的字都记为正确。
4. “历史复习”从本课之前最多选 20 题，每轮最多 5 道包含到期错字的词，其余向前筛查没默过的字；新题不够时，不用错词凑满。优先用已学的册末词语，其次用已审阅的教材补充题或可用的课文词（标注“课文取词”）。题目整词默写、逐字计分，拼音提示不显示汉字。本课用当课复习。待巩固的错字在上次作答后满 5 天（120 小时）才再默；包含这类等待中错字的词不出题。
5. 生字按“写对次数 − 写错次数”计算净正确次数，达到 1 即通过；例如错 2 次，需要累计写对 3 次。同一场默写中，同一个字即使出现在多个词里，也只累计一次作答结果。
6. 古诗词只在当课做整篇默写，不作为历史复习题源。只显示题目拼音，题目、教材所列朝代与作者和全文都由孩子默写，不播放语音。
7. 同一次默写中，只要任意默写字出现在课文题目里，页面主标题和该课所有题卡都会持续把对应字替换为拼音，避免其他题泄露答案；批改时恢复中文题目。
8. 孩子写完后点击“结束默写”，同一页显示全部题目的完整答案；点选错字并完成批改。保存后进入订正页：页面放大显示一次完整错词及已有拼音（古诗显示题目和正文拼音），直接在词中标红错字；第一次写错订正 2 遍，以后每错一次增加 1 遍。
9. 家长看板会汇总打卡、正确率和全部待巩固错字；错字按默写词语归类，不再省略较早的错词。另有“历史错词”统计和完整清单，词语掌握后仍保留，并区分“待巩固 / 已掌握”。两份清单都可一键单独打印。
10. 当课复习或历史复习保存后如果漏标了错字，可在“家长看板 → 最近默写”找到对应记录，点击“补记错字”进入独立页面；较早的记录可先点“查看全部”。补记页面会列出当场题词，锁定已经记录的错字，并允许把其他原判正确的计分字补标为错误。更正会直接修改原记录：作答次数不增加，并同步更新待巩固状态。新记录会保存当场题词和实际计分字；旧记录按当前词库还原，原来判为全对的目标字可直接补记，无法证明当场计分的提示字保持不可选，旧版已整词计错的题不会重复累计。
11. 当课复习和历史复习的批改题卡下方可标记“组词不合适”“读音不准”，两项可同时选择，再次点击可取消。标记会自动保存，不计为孩子的错字。家长可在“家长看板 → 词库问题”集中查看、导出当前列表的 JSON 清单，并在修改词库后标记已处理；也可重新打开。记录保留标记时的完整词语、拼音、目标字和课次，即使重建词库仍可定位原题。

## 词库

当前题库以本次提供的五·四学制教材为准，覆盖二年级上下册、三年级上下册、四年级上册，不用旧教材补齐未提供的册次。

```bash
npm run rebuild:catalog -- /path/to/textbook_codex
```

重建脚本从 `小学语文教材结构化/` 读取课次、识字表、写字表和可解析的古诗，从 `默写词库-教材入库.md` 读取册末词语、拼音和语境。以课次文件核对词语顺序；只有教材标为可挖空的语境会出现在提示中。没有语境时保留听写和拼音提示，不配自拟句。未被词语表覆盖的字优先使用已学教材词语组词，否则出单字题。旧版 `md/` 不再是现行题库的数据源。

重建同时导入 `scripts/textbook/reviewed-prompts.json` 中的 282 条已审阅补充题，并按文件与行号核验教材原文。这些题供当课和历史复习使用，单字均附原句、教材片段或列词。

- `data/ziqu-catalog.sqlite`：新教材词库，不含旧题索引。重建会先校验临时库再替换，**不打开、不替换学习库**。
- `ZIQU_LEARNING_DB_PATH`：独立的学习库路径，保存日后新的默写记录和逐字计分。初始化使用新文件或新数据卷，不覆盖原学习库。

## 从逐字状态开始

将线上备份解压到单独目录后，给新系统创建一个初始化学习库。末尾的起始课名可省略：

```bash
npm run mastery:seed -- /path/to/backup/ziqu-learning.sqlite .cache/new-learning/ziqu-learning.sqlite 颐和园
ZIQU_LEARNING_DB_PATH="$PWD/.cache/new-learning/ziqu-learning.sqlite" npm run dev
```

初始化只读取新教材范围内的逐字作答次数及错误次数，不导入旧场次、题词、错题证据、打卡、时间戳或词库标记，不会覆盖已有数据库。不在新教材字词范围中的字不参与统计或出题。掌握标准不变：写对次数减写错次数达到 1。家长看板默认汇总全部教材（跨册去重），也可按册看；以当前课为进度界线（含本课），后续才首次出现的字单独统计。已学但未默写的字表示尚无计分证据，不等于不会。

可从新学习库导出教材范围内的映射。学习库和导出含个人学习数据，不要提交到仓库：

```bash
npm run --silent mastery:report -- .cache/new-learning/ziqu-learning.sqlite > .cache/new-learning/character-mastery.json
```

## 运行

运行环境使用 Node.js 24，前后端共用同一套出题规则。

```bash
npm install
npm run dev
```

然后打开终端中显示的本地地址。

启动页面只读取课次目录、当前课题目和必要的学习统计，不向浏览器下载完整词库。切课和历史复习由后端按需生成题目；默写记录及其题词索引在打开家长看板时加载。词库查询结果在服务端缓存，学习数据保存在 SQLite 并按需读取；接口支持 gzip 压缩。启动时不会重复保存未改动的学习状态，保存新记录会合并保留尚未加载的历史记录。

生产运行：

```bash
npm run build
npm run start
```

## 代码结构与职责

```text
shared/
  types.ts                 词库、学习状态、默写记录的数据类型
  contracts.ts             HTTP 请求与响应的数据契约
  domain/
    characters.ts          目标字与整词字集、逐字批改键
    catalog.ts             课次范围、词语表与补充组词
    reviewPolicy.ts        掌握标准、历史错字复习间隔
    practice.ts            当课、历史、古诗等题目生成
    reviews.ts             批改结果与原记录补记
    state.ts / wordIssues.ts  状态归一化、词库问题标记
src/
  App.tsx                  页面装配与加载状态
  app/
    useLearningData.ts     加载、请求取消、延迟保存、页面数据合并
    useAppController.ts    页面切换、练习阶段、批改草稿与操作衔接
  features/practice/       默写、古诗题卡、订正、标题遮罩、语音播放
  features/parent/         家长看板、最近记录、补记页面
  components/              跨页面共用的界面组件
  lib/                     浏览器 API 适配、日期与课次展示
server/
  index.mjs / app.mjs      进程启动、服务装配与依赖注入
  routes/                  URL、HTTP 方法与业务服务的对应关系
  http/                    JSON、压缩、静态资源传输
  services/                词库缓存、出题与学习记录的业务编排
  db/                      SQLite 表结构、迁移、连接与读写
  config.mjs               数据路径与运行配置
```

依赖方向：`src → shared`，`server → shared`；`shared` 不依赖 React、HTTP、SQLite 或前后端目录。后端路由调用服务，服务调用数据库模块；界面组件通过回调触发操作，不直接请求接口。`src/lib/api.ts` 按 `shared/contracts.ts` 构造请求、读取响应；这些类型描述现有协议，运行时校验规则沿用原实现。

题目生成和完整词库缓存由后端负责，语音播放、提示、逐字选择和练习阶段由浏览器负责。批改与补记在浏览器调用共享规则后保存状态。

新增业务规则放到 `shared/domain` 的相应模块，新增页面放到对应 `features`，新增接口先更新 `shared/contracts.ts`。`src/lib/scheduler.ts`、`storage.ts`、`wordIssues.ts`、`src/types.ts` 和 `server/db.mjs`、`catalog.mjs` 保留为旧脚本的兼容导出入口，新代码优先引用具体模块。

验证命令：

```bash
npm test                 # 接口、数据库、业务规则与模块依赖边界
npm run prompts:audit    # 真实词库的题目与目标字检查
npm run --silent prompts:coverage  # 册末词语、当课和全册历史模拟题的单字及缺句清单
npm run build           # 严格类型检查、未使用代码检查、生产构建
```

## 部署到服务器

可以直接使用 Docker 启动网站：

```bash
docker compose up -d --build
```

默认访问端口是 `5174`。学习记录保存在 Docker 数据卷 `ziqu-data` 中，更新容器不会丢失；课本词库会随镜像一起更新。播音仍由访问网页的浏览器提供，因此服务器不需要部署语音模型，也没有语音接口费用。
